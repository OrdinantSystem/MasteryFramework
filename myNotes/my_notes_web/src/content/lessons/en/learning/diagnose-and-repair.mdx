## The original attempt

<ProcessDiagram preset="repair" id="repair-process" />

Do not replace a mistaken attempt immediately with a polished solution. Keep the exact work and locate the first step that fails or lacks justification. The diagnosis is a hypothesis to test, not a claim to know what was happening in someone’s mind.

## Types of error

| Difficulty | Ask | Next action |
|---|---|---|
| Conceptual | What does this object mean? | Definition and contrasting examples |
| Logical | Is the direction or quantifier valid? | Counterexample or proof audit |
| Procedural | Which valid step was executed wrongly? | Isolate it and try a new case |
| Strategic | Could I solve it if the theorem were named? | Unlabeled mixed tasks |
| Representational | Can I translate words, symbols, and a diagram? | Translate one relationship |
| Communication | Is the reasoning valid but unwritten? | Add the missing justification |
| Prerequisite | Which earlier idea is missing? | Teach it, then return |

A useful reply says what remains valid, identifies the first issue, suggests a minimal repair, and gives a new verification task. “Practise more” is not yet a diagnosis. Mark a gap repaired after a different independent attempt succeeds; test again later before claiming durability.

## Example diagnosis

A student concludes that a matrix is invertible because none of its entries is zero. The problem is not arithmetic: the proposed criterion is false. The matrix with all four entries equal to 1 has dependent columns and determinant zero. Feedback should correct the criterion and ask the student to inspect a different matrix. Repeating a determinant algorithm without addressing the original claim would leave the misconception unexplained.
