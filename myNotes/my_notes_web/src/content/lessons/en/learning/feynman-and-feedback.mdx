## Explanation from memory

Close the notes and explain one bounded idea to someone new to it. Include what it means, the conditions it needs, why it works, and an example. If a word is doing all the work—“obvious”, “linear”, “convergent”—pause and unpack it. You can speak or write; the important part is reconstructing the reasoning yourself.

## Feedback and revision

Ask a teacher, peer, or AI to identify the first missing assumption or unsupported inference. Compare important corrections with the course source. A fluent explanation can be wrong, and a fluent AI critique can be wrong too. Repair that gap, explain again without help, then try a different application.

<Exercise question="“Every line is a linear map because its graph is straight.” What should feedback check?">

The definition, not the visual impression. A linear map preserves addition and scaling and therefore sends zero to zero. The map g(x) = 2x + 3 does not: g(0) = 3. Ask the learner to explain the distinction between affine and linear, then test a new example.

</Exercise>

## Example: revising an explanation

**First attempt:** “A linear map has a straight-line graph, so 2x + 3 is linear.” The explanation is simple, but it uses the wrong criterion.

**Feedback:** The term “linear” here means preserving addition and scaling. Test the proposed map at zero: g(0) = 3. A linear map must give zero. This identifies a specific confusion between an affine function and a linear map.

**Revision:** “The map x ↦ 2x is linear. Adding 3 translates its output and prevents it from preserving addition.” This replaces a visual description with a checkable reason.

**Further check:** x² also gives zero at zero, so that single test cannot prove linearity. Its failure at h(1 + 1) = 4 while h(1) + h(1) = 2 exposes the missing condition. A good explanation survives such follow-up questions; a polished sentence alone does not show that it does.
