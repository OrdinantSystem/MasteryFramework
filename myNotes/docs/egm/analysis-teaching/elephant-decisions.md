## Decisions on the four smaller findings

- **N1, existing reasoning:** accept the correction to emphasis. Function notation, the full reciprocal estimate and the distinction between legal dependence and arithmetic justification already exist. Mark passages retain/reorder/clarify. Add new explanation only for a named inference gap.
- **N2, predicate wording:** change the proposed sentence to “A predicate is a condition we evaluate at an allowed input.” A condition may have the same truth value at every allowed input.
- **N3, repeated examples:** preserve recurrences that change the proof obligation. Witness verification, construction, uniqueness and excluding unlisted candidates are distinct jobs even when they use the same numbers.
- **N4, disclosures:** keep the selected task visible and its answer disclosed. Use purpose-specific optional groups only where useful. Existing visible practice is evidence against a blanket claim that practice is hidden. Do not flatten every disclosure or impose a global quota.

For example, a core C task can use two initial terms equal to 7 followed by −2 forever, with target −2. A valid proof chooses N=3 for arbitrary positive tolerance and proves every tail distance is zero. The threshold need not be smallest or tolerance-dependent. A written optional transfer task for 2/n may use N>2/epsilon after the additional arithmetic facts are supplied; no new plot engine is warranted.

For each task, the next design must supply its reference argument and observable obligations. Missing a domain, choosing a witness using forbidden later information, proving only a sample, or mishandling strict equality triggers revision of that reasoning step. A hinted success is useful feedback but is recorded separately from unaided completion. These are qualitative checks, not visitor mastery scores or evidence of a percentage learning gain.

## Work envelope and remaining uncertainty

The next proposed investment is limited to three before/after English drafts, their reference solutions, small prerequisite bridges and task observation sheets. Review those drafts before paying the maintenance cost of component work and three-language implementation. If a draft needs another topic, a new mathematical engine, or broad changes to preceding lessons, stop that package and re-scope it rather than silently growing it.

For any retained pilot, list exact affected files before implementation. Three lessons imply nine localized lesson files as a minimum, not a complete estimate. Shared presentation work, relocated content, overview corrections and preservation review are counted separately. Code generation/build capacity is available in this environment; named human mathematical reviewers, native-language reviewers and intended learners have not been arranged. AI editorial review can assist, but it does not create those resources.

Sequence the work as draft → review → retained design → localized implementation → preservation/build/browser checks → learner attempts when available → delayed changed task → scope decision. A delayed check on a later study day can provide different evidence from immediate recognition; the exact interval is a study-design choice, not an established optimum here. Reliable effort ranges and calendar commitments belong to the retained pilot design once its changes and review availability are known. The cost/timeline question therefore remains explicitly open rather than falsely resolved.

Source-supported overview corrections and clearly premature notation can still be addressed if learner access is unavailable. A broad redesign justified by faster learning cannot be treated as validated in that situation. Optional Boolean polish is deferred unless a concrete defect warrants it.
